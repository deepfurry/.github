# Contributing to DeepFurry

[English](./CONTRIBUTING.md) · [简体中文](./CONTRIBUTING.zh-CN.md)

Thank you for your interest in DeepFurry.

We welcome contributions from developers, creators, and users of all experience levels.

## Ways to Contribute

You can contribute by:

- Reporting bugs
- Suggesting features
- Improving documentation
- Fixing issues
- Improving existing features
- Contributing new ideas or implementations

## Before You Start

For small fixes, documentation improvements, and minor changes, feel free to open a pull request directly.

For larger features, architectural changes, or breaking changes, please open an issue first so we can discuss the direction before implementation.

Please check existing issues and pull requests before creating a new one.

## Pull Requests

Keep pull requests focused and easy to review.

A good pull request should:

- Have a clear purpose
- Avoid unrelated changes
- Explain what was changed and why
- Include relevant documentation when needed
- Preserve compatibility unless a breaking change has been discussed

Draft pull requests are welcome for work in progress.

## Commit Messages

Use clear and meaningful commit messages.

English commit messages are recommended for consistency across projects.

For example:

```text
feat: add model provider interface
fix: handle empty response correctly
docs: update installation guide
refactor: simplify workflow state handling
```

Conventional Commits are recommended, but individual projects may define their own requirements.

## Language

Issues and pull requests are welcome in both **English and Chinese**.

English is preferred for code, public APIs, identifiers, and technical documentation intended for international use.

Do not worry about perfect English. Clear communication matters more than grammar.

## Project-specific Guidelines

Individual DeepFurry projects may provide their own contribution guidelines, development setup, testing requirements, or coding conventions.

When project-specific guidelines exist, they take precedence over this document.

## Code of Conduct

By participating in DeepFurry projects, you agree to follow our [Code of Conduct](./CODE_OF_CONDUCT.md).

## Security

Please do not report security vulnerabilities through public GitHub issues.

See our [Security Policy](./SECURITY.md) for responsible disclosure instructions.

---

Thank you for helping make DeepFurry better.
