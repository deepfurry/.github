# DeepFurry Support

[English](./SUPPORT.md) · [简体中文](./SUPPORT.zh-CN.md)

Thank you for using DeepFurry projects.

This document explains where to ask for help and how to choose the right channel.

## Getting Help

### Bugs

If you believe you have found a bug, please open an issue in the affected repository.

Before opening a new issue:

- Check the project's README and documentation
- Search existing issues for the same problem
- Include the project version, environment, and steps to reproduce when relevant

### Feature Requests

Feature requests and improvement ideas are welcome.

Please open an issue in the relevant repository and briefly explain the problem you want to solve and your proposed direction.

For large or architectural changes, discussion before implementation is encouraged.

### Questions and Usage Help

If the repository has GitHub Discussions enabled, please use Discussions for general questions, usage help, and ideas that are not clearly bugs.

Otherwise, you may open an issue if the project does not provide another support channel.

### Security Vulnerabilities

Please do **not** report security vulnerabilities publicly.

Follow our [Security Policy](./SECURITY.md) for private vulnerability reporting instructions.

### Community Conduct

For harassment, abuse, or other community conduct concerns, please see our [Code of Conduct](./CODE_OF_CONDUCT.md).

## Support Scope

DeepFurry is an open-source organization, and support is generally provided on a best-effort basis by maintainers and community members.

Unless explicitly stated by an individual project:

- Response times are not guaranteed
- Private one-to-one debugging is not provided
- Commercial support or service-level agreements (SLAs) are not provided
- Archived or end-of-life projects may no longer receive support

Individual repositories may provide their own `SUPPORT.md`. When they do, the repository-specific policy takes precedence.

## Language

Questions and support requests are welcome in both **English and Chinese**.

Clear information is more important than perfect language.
